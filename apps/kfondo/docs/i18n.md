# 한국어·영어 지원

공개 화면은 `ko`, `en`을 지원합니다. 한국어 URL은 기존 경로를 유지하고 영어 URL에는 `/en`을 붙입니다. 브라우저 언어를 감지하며 명시적 URL과 사용자의 선택을 우선합니다. 관리자 화면은 한국어입니다.

## 번역 관리

- UI 문구는 `messages/ko.json`, `messages/en.json`에 기능별로 추가합니다. 키와 ICU 인자는 두 파일에서 일치해야 합니다.
- 대회명·지역·코멘트·SEO, 연도별 코멘트·공지, 코스명은 관리 화면의 **영어 번역 (선택)**에서 편집합니다.
- 영어가 비어 있으면 한국어 원문을 표시합니다. 영어 SEO 문구는 번역된 이름을 사용하는 기본 템플릿으로 생성합니다.
- 영어 대회 상세 화면에는 한국어 원명을 보조 표시합니다. 검색은 한국어·영어 대회명과 지역, 기존 slug를 지원합니다.
- 대회·코스 slug와 원본 기록 JSON 키는 번역하지 않습니다. 표시용 영어 코스명을 원본 키 대신 기록 집계에 사용하면 안 됩니다.
- 대회 날짜는 한국 시간 기준이고 거리·고도는 km·m입니다. 언어 전환은 선택 쿠키를 1년간 저장한 뒤 현재 query/hash를 보존해 페이지를 다시 엽니다.

## DB 적용과 배포 순서

1. Supabase SQL Editor 또는 승인된 DB 마이그레이션 도구에서 `supabase/migrations/20261002_add_english_content.sql`을 적용합니다. 기존 한국어 컬럼을 보존하는 추가 마이그레이션입니다.
2. 관리자 영어 편집 기능을 사용할 수 있는 버전을 배포합니다.
3. `supabase/migrations/20261002_backfill_english_content.sql`을 적용합니다. 2026-10-02 공개 데이터의 35개 대회·지역과 기존 코스명을 대상으로 하며 이미 입력한 영어는 덮어쓰지 않습니다. 공지·코멘트는 원문이 같은 경우에만 채웁니다. 영문 고유명사는 공식 표기와 대조해 관리 화면에서 보완할 수 있습니다.
4. 공개 영어 화면을 배포하고 양언어 홈·대회 캐시를 재검증합니다. 영어 입력/수정도 한국어와 영어 캐시를 함께 갱신합니다.
5. PostHog의 `locale` 속성과 `language_changed` 이벤트로 사용을 확인합니다.

공개 DB 조회는 `*`를 사용해 영어 필드 추가 전에 읽기 실패를 만들지 않습니다. 관리자에서 영어 필드를 저장하기 전에는 반드시 1번 스키마 마이그레이션을 적용해야 합니다. 운영 DB 마이그레이션은 앱 배포와 별도로 SQL Editor에서 적용합니다.

롤백 시 이전 앱 버전을 배포하고 추가 영어 컬럼은 남겨 둡니다. 원본 데이터는 유지되므로 컬럼 삭제가 필요하지 않습니다.

## 검증

```sh
bun run test --runInBand i18n/i18n.test.ts lib/i18n-records.test.ts app/eventFilter.test.ts lib/stats.test.ts lib/date.test.ts
bun run test:e2e:install
bun run test:e2e:i18n
bun run typecheck
bun run lint
bun run build
```

i18n E2E는 로컬 대회·기록·GPX 서버와 `.next-i18n-test` 빌드 디렉터리를 사용합니다. 운영 DB·메일을 수정하지 않고 기존 개발 서버와 함께 실행할 수 있습니다. 기본 Playwright 테스트와 실행 포트가 다르므로 전용 명령을 사용합니다.

네이버 지도 바탕 지명과 외부 공식 사이트, 사용자 입력 내용은 자동 번역하지 않습니다. 기록 OG 이미지는 기존 규약대로 full 기록 기준으로 생성됩니다. `scope=kom`은 결과 화면과 공유 링크에서 보존되지만 이미지 생성 규약은 query를 전달하지 않습니다.
